# Spec

The canonical design document lives here:

**[Semantic Manifold Game — Design Specification v0.1](./design-specification-v0.1.pdf)**

It is also served in-app at `/docs/design-specification-v0.1.pdf` so you can open it from Play without leaving the instrument.

## What the eleven sections actually cover

1. **What the game is** — path dependence, not blending. Destinations exert pressure; they are not themes.
2. **How Merry plays** — informal spatial language is the interface.
3. **What a state is** — organism, not prompt: traits, invariants, scars, history, uncertainty.
4. **Concept transduction** — nouns become operators. No keyword soup.
5. **Navigation grammar** — direct, via, geodesic, parallel, hover, overshoot, collision, …
6. **Distance metrics** — changing the ruler changes the map.
7. **Path memory** — arriving through wasps is not arriving directly. Recall mutation, semantic recoil.
8. **Structured chaos** — wreckage with a cause. No free weirdness.
9. **Interface** — map, route recipe, inspector, PLAY / LAB, compile.
10. **Architecture** — software owns state; the model interprets terrain.
11. **Operating contract** — the test: `A → C` must not equal `A → B → C`.

Governing sentence:

> Do not ask what the destination looks like. Ask what the current thing becomes by traveling there this particular way.
